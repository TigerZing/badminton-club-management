# Badminton Club

A mobile-first web app for running a badminton club's weekly sessions: members sign up for events, check free courts, and get balanced doubles matches generated by skill level.

## What's inside

| Path | What it is |
| --- | --- |
| `apps/web` | Next.js 15 app (App Router, Server Actions, Auth.js, Tailwind) |
| `apps/crawler` | Playwright worker that fills the court availability cache, run by GitHub Actions |
| `packages/db` | Prisma schema, migrations, client and seed script |
| `packages/matchmaking` | Pure TypeScript doubles matchmaking engine with tests |

## Run it locally

Requires Node 20+, pnpm 10 and PostgreSQL.

```bash
pnpm install
cp .env.example .env            # then fill in the values
cp .env packages/db/.env
cp .env apps/web/.env.local
pnpm db:migrate                 # create tables
pnpm db:seed                    # create the first admin from SEED_ADMIN_*
pnpm db:seed -- --demo          # optional: 20 sample players and an event
pnpm dev                        # http://localhost:3000
```

Checks: `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`.

## Deploy to Vercel with Neon

1. On [vercel.com](https://vercel.com), sign in with GitHub and **Import** this repository.
2. Set **Root Directory** to `apps/web`. Leave the other build settings as they are; `apps/web/vercel.json` runs the database migrations and then the build.
3. Before the first deploy, open the project's **Storage** tab, add **Neon** (Postgres), choose the Singapore region, and connect it to the project. This sets `DATABASE_URL` and `DATABASE_URL_UNPOOLED`.
4. In **Settings → Environment Variables**, add `AUTH_SECRET` (generate one with `openssl rand -base64 32`).
5. Deploy. Then create the first admin once, from your computer, using the production database URL:

   ```bash
   DATABASE_URL="<neon url>" DATABASE_URL_UNPOOLED="<neon url>" \
   SEED_ADMIN_EMAIL="you@example.com" SEED_ADMIN_PASSWORD="<strong password>" \
   pnpm db:seed
   ```

6. Optional, for court crawling: add `DATABASE_URL` as a GitHub Actions secret so `.github/workflows/crawl.yml` can run, and set `GITHUB_TOKEN` (fine-grained, Actions: write) and `GITHUB_REPO` in Vercel so admins can press **Run crawl now**.
7. Optional: add your domain under **Settings → Domains**.

## Matchmaking

`generateRound` in `packages/matchmaking` picks who plays (fewest games tonight, then longest wait), starts from groups of similar skill, then keeps random swaps between courts that lower the total cost:

- 10 × the skill difference between the two teams
- 2 × the gap between the strongest and weakest player on the court
- 30 × each repeated teammate pair, 6 × each repeated opponent pair (pairings from earlier weeks count a quarter)

Admins can change any player before publishing a round.

## Adding a booking site to the crawler

Copy `apps/crawler/src/adapters/example.ts`, adjust the selectors for the site, register it in `adapters/index.ts`, and set the venue's **Crawler key** to the adapter's key in Admin → Venues. Venues without a key are updated by hand.
